# Бизнес-пульс: frontend

React + TypeScript + Vite. Кнопки, поля, типографика и индикаторы загрузки —
[Core Components Альфа-Банка](https://core-ds.github.io/core-components/master/?path=/docs/intro--docs),
корпоративная тема `@alfalab/core-components-themes/corp.css`.

Клиент работает с Go API. Административные экраны источников и качества из PRD
в эту поставку не входят. Макет сценария реализован кодом; отдельный Figma-макет не предоставлен.

## Локальный запуск

Нужен Node.js 22.12+ (проверено на Node.js 24). Из каталога `frontend`:

```sh
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. По умолчанию фронтенд работает с реальным Go API,
который Vite проксирует на http://127.0.0.1:18080. Сначала поднимите корневой
Compose. В окне входа можно войти с учётной записью Go или зарегистрироваться
для синтетической компании из активного CSV, указав её ID и должность. Локальный
Compose включает такую регистрацию; вне него она отключена по умолчанию.

Для автономного демо без Go установите `VITE_DATA_MODE=demo` в `.env.local`.
В этом режиме выберите компанию и должность, затем используйте тестовый аккаунт:

| Компания из CSV             | Логин            | Пароль           |
| --------------------------- | ---------------- | ---------------- |
| `U_80` · обработка металлов | `demo.metal`     | `Metal2026!`     |
| `U_76` · перевозки          | `demo.logistics` | `Logistics2026!` |
| `U_67` · торговля ИТ        | `demo.tech`      | `Tech2026!`      |

Это три проверяемых примера из `data/hackathon/df_Uid_data_hack.csv`, а не
учётные записи обезличенных физических лиц из `df_Fid_Uid_link_hack.csv`.
Должность выбирается из трёх демонстрационных ролей. Учётные данные публичны,
проверяются в браузере и не защищают реальные данные. Пароль не сохраняется:
в `sessionStorage` остаются только выбранные логин, компания и должность до выхода
или закрытия вкладки.

```sh
npm test
npm run build
npm run preview
```

В корневом Docker Compose frontend доступен на http://127.0.0.1:13001.
`docker compose up -d --build` поднимает Go API и фронтенд в API-режиме.
На новой БД новости появятся после добавления источника и его первого опроса.
Для локальной проверки есть явный пример конфигурации:
`docker compose exec api /app/sourcectl create /app/examples/sources/federal-reserve-press.json`.
Он загружает настоящие RSS-публикации; часть записей содержит только заголовок.
Для отдельного демо: `FRONTEND_DATA_MODE=demo docker compose up -d --build frontend`.

## Что работает

- Серверные регистрация, вход, восстановление cookie-сессии и выход. В API-режиме компании и роли приходят из `/contexts`.
- Колесо фортуны в API-режиме выбирает случайную новость из последних сохранённых Go статей. Список загружается через `GET /v0.1/news`, остаётся только в памяти вкладки на пять минут и сбрасывается при выходе. Есть пустое состояние, повтор загрузки и ссылка на безопасный URL оригинала. В деморежиме истории вымышленные и явно помечены.
- Когда профиль или ML ещё не готовы, основной экран показывает последние сохранённые публикации без персонального ранжирования; серверную ошибку он не скрывает.
- Демовход доступен только при `VITE_DATA_MODE=demo`. В API-режиме финансовые остатки и операции не выдумываются.
- Персональная лента, фильтр по теме, поиск по уже загруженным событиям, загрузка следующих страниц.
- Полный анализ при открытии события; поддержка синхронного результата и асинхронного polling.
- Раздельное представление фактов, аналитики банка, AI-выводов и сценариев; оговорки и источники.
- Просмотр сохраненных выдержек и этапов анализа без скрытых рассуждений модели.
- Уточняющий диалог в контексте версии анализа, восстановление истории через API.
- Оценка конкретной редакции анализа; причина и необязательный комментарий для отрицательной оценки.
- Отмена ожидания при смене контекста; старый ответ не показывается как анализ новой компании.
- Десктопная и мобильная верстка, управление с клавиатуры, доступные подписи, reduced motion.

Поиск в текстовом поле — локальный поиск по загруженным карточкам, не поиск по всему корпусу.
Порядок ленты и важность приходят с сервера; frontend их не рассчитывает.

## Демо и реальный API

Скопировать `.env.example` в `.env.local`. Это публичная конфигурация сборки:
ключи моделей, `SERVICE_TOKEN` и другие секреты сюда не добавляются.

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=
VITE_AUTH_START_URL=
VITE_SELF_REGISTRATION_ENABLED=false
```

Перезапустить dev server. Пустой Base URL использует same-origin `/v0.1`;
Vite проксирует его в `http://127.0.0.1:18080`. Для production используйте
same-origin HTTPS через reverse proxy. Саморегистрация выключена по умолчанию
при отдельной сборке; корневой Compose включает её только для локального
стенда с синтетическими компаниями.

API-клиент использует cookie-сессию (`credentials: include`), `cache: no-store`,
CSRF-токен из cookie `csrf_token` и стабильный `Idempotency-Key` для повторов одного
анализа/вопроса. Не отправляет назначенные клиентом `user_id`, `role_id` и профиль
в запросе создания анализа. Все ML-вызовы проходят через Go.

API-режим не подменяет ошибки демонстрационными результатами. Перед входом
интерфейс проверяет `GET /v0.1/me`. Если сессии нет, он отправляет логин и пароль
на `POST /v0.1/auth/login`. Для регистрации сначала проверяет ID компании на
сервере, затем вызывает `POST /v0.1/auth/register` и обычный вход. Сессия живёт
в HttpOnly-cookie; пароль не сохраняется в браузере. `POST /v0.1/auth/logout`
отзывает сессию. При истечении сессии интерфейс возвращается к форме входа.
Прямой переход на `/pulse` тоже проверяет её. Опциональный
`VITE_AUTH_START_URL` оставлен для внешнего способа входа; форма локального входа
от него не зависит.

Саморегистрация на локальном стенде не подтверждает владение компанией и не
готовит профиль для ML. Её нельзя включать в production без проверки полномочий.
При отсутствии готового профиля Go возвращает `409 PROFILE_NOT_READY`, а интерфейс
показывает состояние подготовки профиля.

Демо-история и оценки хранятся только в `sessionStorage` под отдельным синтетическим
ключом. Реальные ответы API frontend в браузерное хранилище не записывает.
Nginx задаёт CSP и другие защитные заголовки, не кэширует HTML и разрешает долгий
кэш только для версионированных статических файлов. TLS и HSTS настраиваются на ingress.
Ключ повторного анализа сохраняется в памяти текущего приложения; восстановление
незавершенных операций после полной перезагрузки требует отдельного контракта.

## Готовность полного пайплайна

Go реализует пользовательские маршруты ленты, анализа, диалога и оценки. В
открытом PR ML Foundation #21 HTTP-сервис пока принимает обработку материалов;
`feed-rankings`, `analyses` и `follow-ups` ещё не опубликованы. До их появления
персональная лента и генерация честно показывают серверную ошибку. Новая локальная
регистрация создаёт черновик профиля; для ленты нужен подготовленный активный
профиль. Демо-режим остаётся способом отдельно проверить интерфейс.

Для сквозного E2E остаются:

1. Понятное название роли. `AvailableContext` возвращает `role_id`, но не
   справочник названий; в демо роль включена в `display_name`, в API frontend
   показывает серверный `display_name` без догадок о значении ID.
2. Просмотр полного профиля и состава группы: отдельного публичного метода пока нет.
3. Разрешение ссылки на точный оригинал доказательства. `Evidence.reference`
   содержит ID версии/чанка, но не URL или название материала. Сейчас отображается
   выдержка, версия и, если передан, URL соответствующего `FeedItem.sources`.
   Для открытия именно цитируемой версии нужен отдельный договоренный ответ сервера.
4. Восстановление активной генерации после перезагрузки.

Типы в `src/types.ts` соответствуют используемой части публичных DTO из
`docs/api/schemas.yaml`. Изменения контракта должны обновлять их вместе с API-клиентом.

## Проверка состояний

В деморежиме доступны адреса:

- `/?scenario=empty` — пустая лента;
- `/?scenario=error` — ошибка загрузки;
- `/?scenario=profile` — профиль не готов;
- `/?scenario=no-contexts` — нет доступных компаний;
- `/?scenario=unauthenticated` — нет сессии;
- `/?scenario=slow` — медленный разбор для проверки переключения компании.

Основной ручной сценарий: открыть событие → проверить основания → задать вопрос →
вернуться к разбору → поставить оценку → переключить компанию. Данные первого
контекста не должны оставаться в новом. Весь контент демо синтетический, включая
раздел аналитики банка: это не реальные новости, прогнозы или позиция Альфа-Банка.

Автоматические проверки покрывают CSRF/cookie/idempotency, пагинацию контекстов,
отмену polling, неподтвержденные утверждения, ссылки, смену контекста, диалог и оценку.

## Структура

- `src/App.tsx` — экраны и пользовательские действия;
- `src/api.ts` — публичный HTTP API, ожидание генераций, чтение истории;
- `src/types.ts` — используемые DTO;
- `src/demo.ts` — отдельный синтетический адаптер;
- `src/styles.css` — сетка, адаптивность и дополнительные стили;
- `src/*.test.*` — проверки поведения;
- `nginx.conf`, `Dockerfile` — раздача сборки и прокси к Go.
