# burmalda

Сервис новостной аналитики для принятия бизнес-решений. Он сопоставляет внешние события с особенностями компании, объясняет возможные последствия и показывает, на каких данных и материалах Альфа-Банка основан вывод.

## Запуск

Нужен Docker с Compose. Из корня репозитория:

```sh
docker compose up -d --build
```

Команда поднимает PostgreSQL, локальное S3-совместимое хранилище, создаёт bucket, применяет миграции, проверяет и загружает [исходный набор данных](data/hackathon/README.md), затем запускает API, воркер опроса и ML-заданий, сборщик состояния, очистку истории и сверку оригиналов. Prometheus, Loki, Tempo, Alloy и Grafana запускаются вместе с ними. Проверка: `docker compose ps` и `curl http://127.0.0.1:18080/health/ready`. Grafana доступна по адресу [http://127.0.0.1:13000](http://127.0.0.1:13000). Остановить процессы: `docker compose down`; данные PostgreSQL остаются в `docker-volume/postgres`, остальные persistent-данные — в Docker volumes.

Фронтенд доступен на http://127.0.0.1:13001. По умолчанию он работает с Go API: вход, регистрация тестовой учётной записи и пользовательские данные идут через сервер. Колесо фортуны и список последних публикаций читают уже сохранённые Go новости без ML. В чистой БД список пуст, пока оператор не добавит источник. Для локальной проверки реальной ленты: `docker compose exec api /app/sourcectl create /app/examples/sources/federal-reserve-press.json`; это настройка примера, а не встроенный источник. Для автономного просмотра макета включите `FRONTEND_DATA_MODE=demo`. Локальная разработка и текущие ограничения полного ML-пайплайна описаны в [frontend/README.md](frontend/README.md).

Локальные пароли и ключи в Compose предназначены только для проверки на своей машине. В частности, для подписи курсоров задан локальный `CURSOR_SIGNING_KEY`, поэтому базовый Go-запуск не требует подготовки `.env`; вне локального Compose его необходимо заменить случайным 32-байтовым ключом в Base64. ML1/ML2 реализованы отдельным Compose-профилем. Для полного Go → ML запуска скопируйте `.env.example` в `.env`, задайте ключ gateway и выполните команду из [инструкции по запуску ML](docs/ml/docker.md). Без `ML_PIPELINE_VERSION` Go не создаёт ML-задания. Лимит текста — 131072 байта. API подключает `/v0.1/me`, `/v0.1/contexts`, `/health/live` и `/health/ready`. Подробности — в [документации бэкенда](backend/README.md).

Импортированные банковские PDF проходят через общий поток `article_versions` → `processing_jobs`; при пустой версии ML-пайплайна задания не создаются. Для передачи нормализованных CSV по запросу ML можно задать `DATASET_API_TOKEN` и использовать закрытый API `/internal/v0.1/datasets/active`. Формат его использования с ML пока не согласован; детали — в [описании набора](data/hackathon/README.md).

## Как войти в тестовый аккаунт

### Обычный режим: настоящий Go API и ML

После запуска Compose дождитесь готовности API:

```sh
curl --fail http://127.0.0.1:18080/health/ready
```

1. Откройте [http://127.0.0.1:13001/pulse](http://127.0.0.1:13001/pulse).
2. При первом входе выберите вкладку **«Регистрация»**. Общая учётная запись с
   заранее заданным паролем в этом режиме автоматически **не создаётся**.
3. Заполните форму:

   | Поле | Что указать |
   |---|---|
   | Ваше имя | Например, «Тестовый пользователь» |
   | Логин | Например, `demo.user`; если занят — выберите другой |
   | Пароль и повтор пароля | Придумайте свой пароль длиной не менее 12 символов |
   | ID компании из набора данных | `U_76` |
   | Должность | «Владелец» |

4. Нажмите **«Зарегистрироваться»**. Интерфейс автоматически выполнит вход.
5. При следующих входах откройте тот же адрес, выберите **«Вход»**, введите
   свой логин и пароль и нажмите **«Войти»**. Учётная запись сохраняется в
   PostgreSQL после перезапуска контейнеров.

Регистрация включена в локальном Compose по умолчанию. Если вкладки нет,
проверьте `AUTH_PASSWORD_LOGIN_ENABLED=true`,
`AUTH_SELF_REGISTRATION_ENABLED=true` у Go API и
`FRONTEND_SELF_REGISTRATION_ENABLED=true` при сборке frontend.
Компания `U_76` должна присутствовать в импортированном наборе; готовность импорта
можно проверить через `docker compose logs data-import`. При изменённых портах
используйте адрес frontend своего стенда вместо `13001`.

Вход сам по себе не включает ML и не создаёт готовые разборы. Для настоящего
анализа нужен [полный запуск ML](docs/ml/docker.md): gateway-ключ, закреплённые
веса и профиль `ml`. Подготовленная ранее карточка другого пользователя не
переносится в новый аккаунт. Порядок применения исправлений PR #36 описан
[отдельно](docs/operations/pr36-integration-fixes.md).

### Автономное демо интерфейса: без Go и настоящих моделей

Для просмотра макета включите этот режим и пересоберите frontend:

```sh
FRONTEND_DATA_MODE=demo docker compose up -d --build frontend
```

Откройте [http://127.0.0.1:13001/pulse](http://127.0.0.1:13001/pulse), выберите
компанию **`U_76`**, должность **«Финансовый директор»** и войдите:

- **Логин:** `demo.logistics`
- **Пароль:** `Logistics2026!`

Это публичные учебные данные для автономного макета. Они **не подходят для
входа в обычный режим Go API** и не проверяют настоящий анализ. Чтобы вернуть
обычный режим, пересоберите frontend:

```sh
FRONTEND_DATA_MODE=api docker compose up -d --build frontend
```
