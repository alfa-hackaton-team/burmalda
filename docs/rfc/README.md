# Предложения для обсуждения (RFC)

TEAM DECISION: RFC содержит обсуждаемое предложение, не является основным источником принятого решения и не разрешает реализовывать вариант как согласованный. Схема из `feature/db-rfc` предварительная до отдельного согласования.

Статусы: DRAFT → PROPOSED → UNDER_REVIEW → ACCEPTED либо REJECTED; заменённый RFC получает SUPERSEDED со ссылкой на новый. Нумерация последовательная; существующие имена из другой ветки сверяются при объединении изменений, без автоматического переименования чужих файлов.

Обязательные сведения: номер и название, статус, авторы, даты создания и обновления. Обязательные разделы: контекст, проблема, цели, что не решается, рассмотренные варианты с преимуществами и недостатками, критерии оценки, подтверждения и эксперименты, предлагаемое решение, последствия, риски, открытые вопросы, принятое решение и связанные документы.

RFC нужен, если выбор затрагивает несколько компонентов, API, хранение или качество, содержит существенные компромиссы и не описывается одной строкой TBD. Сейчас предложены два RFC со статусом DRAFT: векторное хранилище и порядок генерации разбора. Ни один вариант не принят. Для небольших открытых вопросов достаточно [реестра](../planning/decision-register.md).

После ACCEPTED обновляются основные проектные документы, создаётся ADR при архитектурной значимости и добавляются ссылки. REJECTED сохраняет краткую причину, история не удаляется. Объединение RFC с `main` не означает принятие, если статус остаётся DRAFT, PROPOSED или UNDER_REVIEW.
