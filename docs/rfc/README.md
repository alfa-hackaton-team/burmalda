## Структура разбора

Описание начинается с пользовательской или инженерной задачи. Затем перечисляются свойства, которые должны выполняться независимо от реализации. Сравнение подходов отделяет реальные различия: задержку, сложность восстановления, расход ресурсов и влияние на контракты.

Измерения проводятся на одинаковых входных данных, чтобы результат можно было объяснить. Изменение модели, данных и способа хранения одновременно не позволяет понять, что дало улучшение. Поэтому разбор содержит порядок эксперимента и ограничения интерпретации.

Связи с архитектурой, моделью данных и API указывают, какие документы должны оставаться согласованными при изменениях. Подробный разбор нужен там, где краткого перечисления свойств недостаточно для понимания последствий.
