# Документация проекта

Версия описания: 0.1. Дата: 2026-10-22.

Документы описывают продукт с трёх сторон: что получает пользователь, как устроена обработка данных и как компоненты обмениваются результатами. Общий принцип — каждый персональный вывод связан с конкретным событием, особенностями бизнеса и проверяемыми источниками.

## Как читать

Начать знакомство с продуктом удобно с PRD. Архитектура показывает полный путь от загрузки материалов до ответа пользователю. Модель данных закрепляет единый смысл сущностей, а спецификации API — их представление при обмене между компонентами. Документы ML, загрузки и наблюдаемости раскрывают отдельные части этой цепочки.

## Общие правила описания

В PRD используются пользовательские понятия: компания, группа компаний, событие, персональный разбор и уточняющий вопрос. В технических документах рядом с ними приводятся имена сущностей API: `Company`, `CompanyGroup`, `Event`, `Insight`, `Conversation`. Это позволяет читать описание продукта без знания внутренней структуры и сохранять точность взаимодействия разработчиков.

Идентификаторы Cxx связывают описание с требованиями кейса; FRxx и NFRxx обозначают функциональные и нефункциональные требования. Состояния источников, генерации и проверки утверждений относятся к работе продукта: они определяют, что пользователь и система делают при успехе, ошибке или недостатке данных.

Форматы обмена описываются в общих схемах и используются обеими спецификациями API. Таблицы, индексы и транзакции относятся к физической модели БД; JSON-представление ответа не требует отдельной таблицы для каждого объекта. При изменении сущности её смысл, API и хранение рассматриваются совместно.

Технологические параметры описываются через назначение, ограничения и измеримые критерии. Например, время ответа оценивается по реальной цепочке обработки, а способ поиска — на размеченном наборе запросов. Такое описание сохраняет требования независимо от конкретной библиотеки или способа развёртывания.

Риски, этапы реализации и распределение ответственности находятся в [архитектуре](architecture/architecture.md#риски-реализации).
