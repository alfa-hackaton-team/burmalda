## Что изменено

- Добавлены ML-ручки `feed-rankings`, `analyses`, `analyses/{id}`, `follow-ups`: service token, валидация, постоянная очередь и `ml-analysis-worker`. Повтор одного ключа не создаёт второй платный запуск. Потерянный RUNNING через 5 минут становится FAILED без автоматического повторного LLM-вызова.

## Как продолжить

Из корня репозитория; первая строка нужна на этом Mac, если `docker` отсутствует в PATH:

```sh
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
docker compose -f compose.yaml -f compose.ml.yaml --profile ml up -d --build
docker compose -f compose.yaml -f compose.ml.yaml --profile ml ps
docker compose -f compose.yaml -f compose.ml.yaml --profile ml logs --tail=80 api ml-api ml-analysis-worker ml-worker
curl http://127.0.0.1:18080/health/ready
```

Vite запущен отдельно: из `frontend/` — `VITE_DATA_MODE=api VITE_SELF_REGISTRATION_ENABLED=true npm run dev`. Подробности: [запуск ML](../ml/docker.md).

Ключ находится в корневом `.env`, исключённом из Git: **не печатать и не коммитить**. Веса — `docker-volume/models` (~2,2 ГБ), БД — `docker-volume/postgres`; не удалять при обычном перезапуске. Локальные smoke-скрипты, результаты и credentials тестовой учётной записи — `.local/demo-smoke/`, также вне Git. Для собственного входа зарегистрироваться в интерфейсе, например с компанией `U_76`; учебные demo-логины не работают.

## Ограничения / следующий этап

- Лента пока общая, по новизне добавления; персональное ранжирование ещё не откалибровано. Неизвестные даты остаются null.
- Реальная модель иногда возвращает недостаточно подтверждённый ответ: `VERIFICATION_FAILED` или `INSUFFICIENT_EVIDENCE`. Проверки не отключались. Следующая задача — устойчивость генерации и понятные отказы, затем качество ранжирования.
- На CPU возможны очереди. Режим `semantic` с повторным embedding/reranker дал таймауты под нагрузкой; текущий exact-evidence путь прошёл сквозной тест.
- Один импорт прервался при восстановлении PostgreSQL во время тяжёлых тестов; повтор завершился успешно. Далее тесты вынесены в отдельный `burmalda-testdb` (15432), сейчас остановлен. Не запускать тесты на рабочей БД демо.
- Пользовательские untracked `docs/ml/ml1/`, `ml/evaluation/reports/` и `.DS_Store` сохранены без добавления в Git.
