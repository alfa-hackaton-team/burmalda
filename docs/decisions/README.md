# Architecture Decision Records

TEAM DECISION: ADR хранит уже принятое архитектурно значимое решение, а не варианты к обсуждению. Исходные ограничения и статусы проектных решений перечислены в [реестре](../planning/decision-register.md); предложения обсуждаются через RFC.

После принятия значимого выбора: `NNNN-short-title.md` с датой, Status ACCEPTED, Context, Decision, Alternatives considered, Evidence, Consequences, Risks и Related RFC/docs. Указать авторов, участников review и основание принятия решения.

Accepted RFC → при необходимости ADR → обновление architecture/model/API/ML/PRD → cross-links → реализация. Не создавать ADR на каждый field и не объявлять весь initial design принятым по наличию одного ADR. Отменённый ADR сохраняется с SUPERSEDED и ссылкой на замену.
