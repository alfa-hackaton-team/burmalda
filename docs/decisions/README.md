# Записи об архитектурных решениях (ADR)

TEAM DECISION: ADR фиксирует уже принятое архитектурно значимое решение, а не варианты для обсуждения. Исходные ограничения и статусы решений перечислены в [реестре](../planning/decision-register.md); предложения обсуждаются через RFC.

После принятия значимого выбора создаётся `NNNN-short-title.md` с датой и статусом ACCEPTED. Обязательные разделы: контекст, решение, рассмотренные альтернативы, подтверждения, последствия, риски и связанные RFC или документы. Указываются авторы, участники рассмотрения и основание принятия решения.

Принятый RFC → при необходимости ADR → обновление архитектуры, модели, API, ML и PRD → взаимные ссылки → реализация. Отдельный ADR не нужен для каждого поля; принятие одного ADR не означает принятие всего проекта. Заменённый ADR сохраняется со статусом SUPERSEDED и ссылкой на замену.
