# Изменения после ревью PR №6

Редакция 1.1 рабочего комплекта ML v1. Основа: PR №6, commit b23c15948d9d3be8439deea6f82db0473fe92a95. Контракт ещё не выпущен; сервис и миграции не реализованы.

1. **Контекст уточнения.** FollowUp содержит initial_insight со снимком профиля, события, исходным разбором, claims/evidence и историческими чанками. История ответов также хранит структурированные основания. Fixture спрашивает о причине первоначальной рекомендации и цитирует исходный claim.
2. **Идентификаторы.** У уточнения отдельный trace_id и parent_trace_id исходного анализа. Проверка связывает запрос/ответ и запрещает общий trace у двух разных запусков. Повтор той же операции сохраняет исходные ID.
3. **API и типы утверждений.** Логический ML v1 отделён от публичного API v0.1. Внутренний HTTP анализ ссылается на общую машинную схему. claim_type сохраняет бизнес-назначение; knowledge_type и verification_status передают тип знания и проверку. Правила адаптера — api-compatibility.md, пример публичного результата — ../api/examples/insight-ml-v1.json.
4. **Хранение.** В целевой схеме insight_claims описаны knowledge_type, verification_status, assumptions, time_horizon. Эти поля требуют миграции backend до интеграции; существующей миграции не заявлено. Исторические reference-файлы помечены как снимки.
5. **Владельцы.** Профили/события/агент — ML2; качество корпуса/индекс/поиск — ML1. Функции прежнего ML3 распределены в architecture.md. Для загрузки сохранена описанная в проекте граница Go: backend ведёт реестр, воркер, оригиналы и версии, ML1 согласует качество. Это рабочее решение C04; конкретные исполнители и механизм надёжной доставки требуют командного согласования.
6. **Проверки.** Добавлены отрицательные регрессионные тесты, проверка полной JSON Schema, ссылок HTTP и публичного примера. Смысловое качество, авторизация по БД, платные вызовы и восстановление воркера остаются задачами реализации.
