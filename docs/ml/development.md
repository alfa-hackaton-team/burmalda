## Следующая работа ML1

1. Прогнать весь банковский корпус через R02 и зафиксировать FAIL/WARNING и ограничения извлечения.
2. Для R05 выбрать embedding-модель/размерность, chunking/overlap, стабильные ID и историю переиндексации.
3. Определить политику пустого title будущего Chunk и доступ к page mapping Go; R02 хранит исходные данные без догадок.
4. Подключить хранилище, фильтры и точное чтение исторических чанков с проверкой доступа.
5. Реализовать надёжную готовность: поздно проиндексированная версия не должна теряться из-за курсора по retrieved_at.
6. Измерить Recall, качество выдачи, задержку и покрытие на общем наборе.

## Интеграция ML2/backend

ML2 строит профиль/события, bounded search, claims, verification и follow_up. Backend предоставляет исходные данные, права, операции и публикацию. HTTP ML, хранение результатов, lease, бюджеты и общая pipeline_version требуют подключения владельцем ML-сервиса.

Проверить до рабочего запуска: повтор без повторной генерации, восстановление после сбоя, исходные evidence после обновления документа, сохранение claims/provenance, различие empty/partial/error, недостаток данных и отсутствие банковской позиции. PASS R02 не закрывает полную article-processing.
