# Исходный набор аналитических данных Альфа-Банка

В каталоге лежит фиксированная копия 12 файлов: три CSV из папки «Данные для участников» и девять PDF из папки «Аналитические материалы». Рядом с каждым PDF лежит предоставленный TXT с тем же именем без расширения PDF. Самостоятельно сгенерированные `.ocr.txt` удалены; импорт использует только предоставленные тексты. `manifest.json` содержит SHA-256 оригиналов и текстовых слоёв.

`data-import` перед запуском API и воркера сверяет файлы с манифестом, проверяет активный набор в PostgreSQL и наличие PDF в локальном S3. При первом запуске CSV загружаются в таблицы `dataset_*`, PDF сохраняются как оригиналы вместе с предоставленным TXT. Повторный запуск с тем же набором ничего не импортирует. Если файл изменён без обновления манифеста или отсутствует, запуск завершается ошибкой.

После проверки импорта банковские PDF связываются со стандартными `article_versions` и `raw_artifacts`. Источник имеет `source_role=bank`, отключён от опроса и не выдаётся за новость. Связь хранится в `dataset_bank_report_documents`, диапазоны байтов предоставленного текста для каждой страницы — в `dataset_bank_report_pages`. При заданных согласованной версии пайплайна и лимите текста `data-import` создаёт идемпотентные `processing_jobs`; обычный ML-воркер отправляет их по текущему HTTP-контракту. Режим «только индексировать» пока не согласован с ML, поэтому отдельное поле режима не передаётся; успешный ответ с пустым `event_ids` допустим. Все девять TXT сейчас меньше подтверждённого предела 131072 байта.

Исходные строки CSV сохраняются с номером строки. При импорте пробелы по краям полей убираются, пустые поля становятся `NULL`. Для текущих расчётов используйте `active_dataset_company_profiles`, `active_dataset_payments` и `active_dataset_person_company_links`: они выбирают активную версию, исключают точные дубли и не допускают связи с конфликтующим идентификатором компании. Представления с суффиксом `_clean` сохраняют доступ к историческим версиям через `bundle_id`. Разные платежи одной пары компаний не объединяются, поскольку в файле нет периода и идентификатора операции. Если одному идентификатору компании соответствуют разные профили или одной паре физлицо–компания — противоречащие географические данные, записи исключаются из чистого представления и фиксируются в `dataset_profile_conflicts` или `dataset_person_link_conflicts`. Номер строки остаётся ссылкой на оригинальный CSV. Счётчики нормализации хранятся в `dataset_normalization_runs`.

Для передачи CSV в ML подготовлен закрытый API Go. Он включается только при заданном `DATASET_API_TOKEN` (сервисный секрет), доступен по `GET /internal/v0.1/datasets/active` и возвращает `bundle_id`, `manifest_sha256`, версию нормализации и `snapshot_id`. Строки выдаются по `GET /internal/v0.1/datasets/active/{companies|payments|person-links}?snapshot_id=...&after=0&limit=500` с `Authorization: Bearer <DATASET_API_TOKEN>`. Максимум — 500 строк за запрос; `next_cursor` передаётся как следующий `after`, `null` означает конец. `snapshot_id` меняется и при новой поставке файлов, и при изменении правил нормализации. Если снимок уже неактуален, сервер возвращает 409: клиент начинает чтение заново с новой версии. `row_no` и `bundle_id` остаются в каждой записи для происхождения; `pay_amt` передаётся строкой без потери точности. Это черновой контракт Go → ML для получения данных по запросу. ML-команда ещё не согласовала потребление этого API, способ запуска перестроения профиля и подтверждение обработанной версии набора; автоматически отправлять миллионы строк как статьи нельзя.

Тексты TXT загружаются без изменения содержимого. Поддерживаются маркеры `=== Страница 7.1 ===` и `[Скриншот 3.1]`: номер после точки задаёт страницу внутри документа. Метод извлечения отмечается как `provided-text`, статус — `PROVIDED`; собственный OCR не запускается. Число размеченных страниц сравнивается с PDF. Несовпадение сохраняется как `PAGE_COUNT_MISMATCH` в `text_issues` и `extraction_issues`, не дополняя текст выдуманными страницами.

При замене TXT обновите его SHA-256 в `manifest.json`; при замене PDF обновите также хеш и размер оригинала. Изменение манифеста создаёт новую версию набора и новые версии изменившихся текстов, сохраняя прежние ссылки. Названия PDF и TXT должны совпадать до расширения. В имени `ALFA_Russian_Steels_1K21PreviewUpdate_15Apr2021.pdf` используется латинская `K`, как в предоставленном TXT.

Набор содержит псевдонимизированные банковские данные. Перед публикацией репозитория проверьте условия распространения исходных файлов.

Миграция `000017` сохраняет происхождение текста и безопасный снимок источника. Общая команда `mlctl enqueue` умеет поставить сохранённые версии любых источников в очередь без повторной загрузки; `mlctl export` готовит примеры запросов без отправки в ML. Подробнее — [управление корпусом](../../docs/operations/ml-ingestion.md).

Миграция `000018` добавляет статус предоставленного текста и диагностику расхождения количества страниц. Старые OCR-версии в БД остаются историей; на диске их текстовые файлы больше не нужны.
